## Context

Tham khảo `docs/specs/FRONTEND_SPEC.md` mục 3.6 (ghi evidence), 4 (Backend API), 5 (Evidence Report), 8 (IPFS), 9 (error handling), 10 (responsive), 11 (accessibility).

Backend API (đã code, 37 tests pass):
- `POST /verify-evidence` body: `{ "trade_id": 1 }` → AI chạy → trả `{ "trade_id", "risk_score", "flagged", "report" }`

- `GET /trade/{id}` → trade info từ chain cache
- `GET /health` → health check

## Implementation constraints

- `PINATA_JWT` PHẢI ở server-side (`app/api/pin/route.ts`), KHÔNG có tiền tố `NEXT_PUBLIC_`
- `keccak256` dùng `viem` (`import { keccak256, toBytes } from 'viem'`)
- Evidence hash: `keccak256(toBytes(ipfsUri))` — khớp đúng logic trong `backend/chain.py` function `evidence_hash_of()`
- Report JSON verify: dùng cùng cách hash mà backend dùng (`keccak256(JSON.stringify(report))` — kiểm tra thứ tự key)
- Error handling: toast (sonner) cho lỗi tx, hiện revert reason nếu có
- IPFS gateway: dùng `NEXT_PUBLIC_IPFS_GATEWAY` + CID để hiển thị ảnh (thay thế `ipfs://`)
- Ảnh keypoint: backend trả base64 PNG trong field `visual_match` — hiển thị `<img src="data:image/png;base64,...">`
